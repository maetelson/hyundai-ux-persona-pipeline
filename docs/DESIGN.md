# 현대차 FoD 페르소나 파이프라인 설계 (v0.1, 2026-10-09)

기반: `maetelson/persona-pipeline`의 인프라 + 롯데마트 AI 페르소나 방법론 + 공개 사례 리서치.
원칙: **기능이 아니라 사용자의 순간에서 출발**(킥오프), **근거가 없으면 주장하지 않는다**(레포).

---

## 0. 한 장 요약

```
수집 ─▶ 정규화·중복제거 ─▶ 스팸/체험단 필터 ─▶ 층 판정(A/B/제외)
   ─▶ LLM 멀티라벨(상황·니즈 / 저니·태도 / 생애단계 단서)
   ─▶ ① 테마 지도: 코드 공출현 PMI + Leiden
   ─▶ ② 페르소나 군집: 게시글×상황니즈 이진벡터 LCA
   ─▶ 프로필 덧입히기: 저니·태도·생애단계·출처 (군집 입력 아님)
   ─▶ 게이트(안정성·출처지배·데모 표시 기준) ─▶ 설문 타이핑툴
```

| 결정 | 선택 | 근거 |
|---|---|---|
| 군집 단위 | 게시글 (코드 2개 이상) | 작성자 식별이 소스마다 불안정. 코드 네트워크는 "사람"이 아니라 "테마" |
| 군집 입력 | 상황·니즈 코드만 | 저니·태도·연령을 넣으면 FoD 글/일반 글, 단서 유무로 갈라짐 |
| 페르소나 방법 | LCA (+ k-modes·Jaccard 계층군집으로 교차확인) | 이진 멀티라벨에 맞고, 설문 세분화 표준이라 설문과 같은 언어 |
| 연령 | 생애단계 라벨 → 사후 프로필, 기준 미달 시 "판단 불가" | 관찰되는 건 연령이 아니라 생애 사건 |
| 규모(%) | 텍스트 비율은 참고, **설문 비율이 기준** | 온라인은 말 많은 사람 편향 |

## 1. 코퍼스: 두 층

| 층 | 정의 | 용도 |
|---|---|---|
| **A. FoD 직접** | FoD·커넥티드 구독·스토어·특정 FoD 기능(원격 주차, 테마, 스트리밍 등) 언급 | 저니 단계별 반감·장벽, 귀속·요금 인식 |
| **B. 운전 상황** | FoD 언급 없이 주차·승하차·아이 동승·장거리·악천후·가족 공유·차 교체 등의 불편/니즈 | 페르소나 군집의 몸통(순간·상황) |
| 제외 | 매물, 시세, 정치, 사고 과실 다툼, 단순 뉴스 전재, 광고 | |

A와 B는 **같은 상황·니즈 코드 체계로 라벨링**한다. 그래서 군집 입력은 한 가지 언어이고, A층 글은 저니·태도 코드를 추가로 갖는다.
→ 군집이 "FoD 글 vs 일반 글"로 갈리지 않으면서, 각 군집에 "이 사람들은 FoD 어디서 막히나"를 덧입힐 수 있다.

**해석**
- 키 없이 확보 가능한 A층은 **약 3,500~4,000건**: 기아 리뷰 약 3,000 + 앱 리뷰 중 FoD 관련 수백 건(Play 전수 17,080건 × 2~5%).
- 앱 리뷰 키워드 매칭의 정밀도는 표본으로 보면 절반 정도다. "유료인데 오류" 같은 커넥티드 요금 불만이 섞이는데, 이는 관리 단계 근거로는 유효하다. → LLM 층 판정 필수.
- 기아 리뷰는 테마 쏠림 + 구매자 한정 + 이벤트 편중이라 단독으로는 페르소나 몸통이 못 된다. 상품·차종 메타가 있어 **저니(인지·만족) 근거**와 **차종 대체지표**로 가치가 높다.
- 페르소나 군집에 필요한 B층(상황)·생애단계 단서는 이 소스들에 거의 없다 → **네이버 블로그·유튜브(키 필요)와 게시판 크롤링이 성패를 가른다.**

### 2.3 NAVER API HUB 운용 (2026-07 이관 반영)

검색 API는 developers.naver.com에서 네이버 클라우드 **NAVER API HUB**로 이관됐다(신규 신청은 2026-07-31부터 HUB만, 구 키는 2027-06-30 종료).

| 항목 | 값 (공식 문서 2026-09-17 기준) |
|---|---|
| 엔드포인트 | `https://naverapihub.apigw.ntruss.com/search/v1/{blog,cafearticle,news,webkr}` |
| 헤더 | `X-NCP-APIGW-API-KEY-ID`, `X-NCP-APIGW-API-KEY` (Application 인증 정보. IAM 키 아님) |
| 파라미터 | `query`, `display` ≤100, `start` ≤1000, `sort` sim/date |
| 한도 | 일 25,000 / 월 775,000 (검색 카테고리 합산), 키당 50 RPS |
| 요금 | 한시적 무료. 유료 전환은 사전 공지. 무료 기간엔 한도 도달 시 과금 대신 차단 |
| 가입 | NCP 계정 + 신용카드 등록 필요(후기 기준) |

**무료로 묶어 두는 장치 (3중)**
1. 콘솔: Application > [한도 및 알림]에서 **일 20,000 / 월 600,000** 한도 설정 + 50·80% 알림, 통보 대상자 등록(안 하면 알림 안 옴).
2. 코드: `pilot/naver_search.py`가 일별 호출 수를 `data/naver_calls.json`에 기록하고 `NAVER_DAILY_BUDGET`(기본 20,000)에서 멈춘다. 429가 반복되면 중단.
3. 운영: 유료 전환 공지 확인 전까지만 대량 수집. 키는 이 프로젝트 전용(같은 키를 다른 서비스와 공유하면 사용량 합산).

**호출 예산**
- 모수 측정 `count`: 쿼리당 엔드포인트 2개 × 1회 → A층 24쿼리 = 48회.
- 수집 `collect`: 쿼리당 최대 2 엔드포인트 × 2 정렬 × 10페이지 = 40회 → A층 24쿼리 ≈ 960회, B층 300쿼리여도 ≈ 12,000회. **하루 안에 끝난다.**
- 증분: 이후 매일 `sort=date` 첫 1~2페이지만.
- 병목은 한도가 아니라 **쿼리·정렬당 1,000건 상한**과 **스니펫만 오는 응답**. → 쿼리를 기능 × {후기, 가격, 구독, 해지, 차종} 조합으로 잘게 쪼개고, 블로그 본문은 링크로 따로 받는다(이건 API 호출 아님).

### 2.4 쿼리 맵 (A층 시드, 네이버·유튜브 공통)

- 상품: 블루링크 스토어, 기아 커넥트 스토어, 커넥트 스토어, FoD, 기능 구독, 차량 구독 서비스
- 기능: 원격 스마트 주차 보조(RSPA), 원격 주차, 디스플레이 테마, 라이팅 패턴, 스트리밍 플러스, 스마트 회생, 빌트인 캠
- 요금: 블루링크 유료, 블루링크 무료 기간 끝, 커넥티드 요금, 기아 커넥트 연장
- 비교: BMW 열선 구독, 테슬라 FSD 구독, 테슬라 프리미엄 커넥티비티
- 1,000건 상한 대응: 기능 × {후기, 가격, 구독, 가치, 해지, 차종명} 조합, `sim`+`date` 둘 다, 매일 `date` 증분

B층은 상황 키워드(좁은 주차장 문콕, 아이 카시트 태우기, 학원 픽업, 장거리 졸음, 눈길 주차, 와이프 운전 연습, 차 바꿀 때 등) × 차종으로 확장. 롯데마트처럼 키워드 탐색 → 상위 글의 공동 언급어로 쿼리 확장(레포 `01_5_expand_queries_from_raw` 재사용).

## 3. 정제

1. **정규화**: 레포 `RawRecord` 스키마 그대로 (`source, raw_id, url, title, body, comments_text, created_at, author_hint, source_group…`). 작성자는 해시로 가명화.
2. **중복 제거**: 정규화 해시(정확) + MinHash LSH 문자 5-gram, Jaccard≥0.8(근사). 퍼나르기·블로그 복붙 제거.
3. **스팸/체험단**: "소정의 원고료/협찬/체험단", URL·전화번호 밀도, 동일 작성자 반복, 딜러 홍보.
4. **층 판정**: 규칙 1차(키워드) → LLM 2차(샘플로 기준 고도화) → 전수. 롯데마트 3단계와 동일.
   - 유효 예: 원격 주차를 우리 아파트에서 써 봤다 / 블루링크 무료 끝나서 고민 / 아이 태울 때 옆 차 때문에 문을 못 연다
   - 제외 예: 매물·시세, 사고 과실 논쟁, 신차 출시 기사 전재, 튜닝 자랑

## 4. 라벨링 (TnT-LLM 방식)

### 4.1 코드북 3묶음

**(1) 상황·니즈 코드 — 군집 입력** (초안, 파일럿 데이터로 확정)

| 대분류 | 코드 예시 |
|---|---|
| S1 주차·승하차 | 좁은 칸 승하차, 문콕 걱정, 기계식/지하 주차, 평행주차, 원격 전후진 |
| S2 아이·가족 동승 | 카시트 태우기, 학원·등하교 픽업, 아이 콘텐츠·화면, 동승자 공조 |
| S3 장거리·피로 | 출퇴근 정체, 고속도로 졸음, 명절·여행 장거리, 혼자 운전 |
| S4 날씨·계절 | 겨울 예열·성에, 여름 선공조, 눈길·빗길 |
| S5 운전 서툰 가족·공유 | 초보 배우자, 부모님 운전, 프로필·설정 바뀜, 누가 결제하나 |
| S6 차 바꿈·보유 | 교체 고민, 중고 매각, 오래 타기, 리스·렌트 |
| S7 비용 계산 | 월 고정비, 보험 할인 상계, 유지비, 옵션 값 |
| S8 개인화·즐거움 | 테마·조명·사운드, 캐릭터·스포츠 팬, 차 꾸미기 |
| S9 보안·안심 | 도난, 외진 곳 주차 감시, 블랙박스·빌트인캠 |
| S10 디지털 습관 | 폰으로 차 제어, 차 화면 조작 불편, 음성 |

**(2) 저니·태도 코드 — 프로필용 (A층만)**
- 저니 9단계: 발견, 이해, 확인, 구매, 활성화, 인지, 관리(연장·해지), 정산, 양도·취소
- 태도: 반감(HW 잠금·이중결제), 수용(SW 진보), 망설임, 사용 후 만족, 불신(고지·해지), 계산(본전), 귀속 우려
- 시드: Notion 인사이트 8개·가설 5개 → 코드 정의의 초기값

**(3) 생애단계 단서 — 프로필용** (5절)

### 4.2 절차
1. 시드 코드북 → LLM이 500건 샘플에 적용하며 코드 추가·병합·분할 (2~3회 반복).
2. **골드셋**: 팀원 2명이 300건 블라인드 라벨 → κ 확인 → LLM 코드별 정밀도·재현율 보고. 기준 미달 코드는 정의 수정 또는 삭제.
3. 전수 라벨링. 대량 B층은 LLM 라벨로 학습한 경량 분류기로 비용 절감(선택).
4. 프롬프트·코드북 버전 고정, 결과에 버전 기록.

LLM 실패 유형 체크(MIT 2025): 모호한 목표, 한 코드에 니즈 여러 개, 근거 없는 추론 → 코드마다 "근거 문장 인용" 필드 필수.

## 5. 생애단계·연령

| 생애단계 | 1순위 본문 단서 | 추정 연령 |
|---|---|---|
| 첫차·1인 | 첫차, 사회초년생, 자취, 첫 할부, 면허 딴 지 | 20~30대 초 |
| 영유아 가족 | 카시트, 유모차, 아기, 어린이집 | 30대 |
| 학령기 가족 | 초등·학원·등하교 픽업, 애 둘, 카니발 | 40대 |
| 독립·교체기 | 애들 다 커서, 대학생 자녀, 부모님 병원, 은퇴 | 50대 이상 |
| 불명 | 위 단서 없음 | — |

- **1순위**: 본문 자기 진술·생애 사건 (LLM이 근거 문장과 함께 추출, 근거 없으면 불명)
- **보조(별도 집계)**: 채널 prior(82쿡, 디시 등), 차종 대체지표, 카페명. 1순위 통계와 섞지 않는다. 섞으면 군집 연령 = 군집의 채널 구성이 되는 순환.
- **사용 안 함**: 입력 습관(마침표 등)
- 성별: "와이프/남편" 진술만. 추정치는 불확실성 표기.

**표시 게이트**: 군집 내 1순위 단서 보유율 ≥30% **그리고** ≥100건일 때만 생애단계 분포 표시, 아니면 "판단 불가". (값은 파일럿 후 조정)

## 6. 군집화

### 6.1 테마 지도 (니즈가 어떻게 묶이나)
- 노드=상황·니즈 코드, 엣지=같은 글 공출현을 **PMI/lift로 정규화** (원시 빈도 금지: 흔한 코드끼리만 연결됨).
- Leiden, seed 50회 → 공동배정 행렬로 안정성, modularity Q 보고.
- 산출: "니즈 테마"로만 보고. 사람 수·연령을 붙이지 않는다.

### 6.2 페르소나 군집 (어떤 사람 유형이 있나)
- 입력: 상황·니즈 코드 ≥2개인 게시글의 이진 벡터, 상위 20~30 코드 (LCA 과적합 방지).
- 주 방법: **LCA** (k=2~10, BIC/엔트로피, nrep≥10). Python: `stepmix`.
- 교차확인: k-modes, Jaccard 계층군집 → 방법 간 ARI.
- 보조: 니즈 패싯 문장(LLM 요약 1줄) 임베딩(KURE-v1 / bge-m3) + BERTopic → 코드북 누락 탐지용, 페르소나 정의엔 안 씀.
- 이름·서술: 사람이 군집 확정 → LLM이 서술(대표 인용 연결). 대표 글은 레포 `example_selection` 재사용.

### 6.3 게이트 (레포 readiness 개념 적용)

| 게이트 | 기준 | 미달 시 |
|---|---|---|
| 안정성 | 부트스트랩 군집별 Jaccard ≥0.75 (≤0.5 해체) | 병합 또는 "후보"로 강등 |
| 출처 지배 | 한 출처 >70% 또는 leave-one-source-out 시 소멸 | "출처 의존 군집" 표기 |
| 근거 규모 | 군집 ≥5% 그리고 ≥200건 | tail 진단으로만 |
| 데모 표시 | 5절 기준 | "판단 불가" |
| 설문 확인 | 설문 재군집과 ARI·비율 대조 | 설문 쪽을 채택 |

## 7. 설문 연결

1. 군집별 시그니처 코드(lift 상위 3~5) → 상황형 문항 ("최근 한 달, 옆 차 때문에 문을 다 못 열고 타고 내린 적이 있다").
2. A층 저니 장벽 → 별도 문항 (Notion 인사이트의 설문 문항 초안 활용).
3. 타이핑툴: LLM이 게시글을 대신해 시그니처 문항에 응답 → (문항 응답 → 군집) 학습 → 판별분석/로지스틱 → 골든 질문 선정.
4. 설문 응답자 배정 + 설문 데이터 단독 LCA → 텍스트 군집과 ARI. 규모·연령은 설문 기준.
5. 설문 필수 항목: 연령(10세 단위), 생애단계, 보유 차종·연식, FoD 구매/인지 경험, 교체 예정.
